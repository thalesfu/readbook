# 19: 修转 48 kHz 的镜像，试高频处理

Type: prototype（HITL）
Status: resolved
Blocked by: 17, 18

## Question

17 号票查用户戴 AirPods Pro 3 听到的"电子颤音"，发现有两部分（`books/wa2/trials/anchor-rule/锚点挑选规则-对比.md` 最后两节）：
- **转 48 kHz 的镜像**，这是我们自己的 bug：
  - `bakeoff.to48k` 用线性插值（`np.interp`）把 IndexTTS-2.5 的 22.05 kHz 输出转成 48 kHz，没有抗镜像滤波；
  - 11 kHz 以上多出一层镜像：成品 12–16 kHz 有 −33 dB，比 10–11 kHz 的 −39 dB 还高；
  - 同样的写法还有两处：`bakeoff.cmd_index`、`voices.Pak.audio`（读游戏原声）。Qwen3 的 24 kHz 输出也走 `to48k`。
- **IndexTTS-2.5 原始输出自带的**：在 8 kHz 以下，后期去不掉。用户在 `out/rawanchor/ab/全员/`（不进 git）听过几种处理：
  - 缓低通（1500 Hz 起每倍频程 −6 dB）"确实变轻了"，代价是声音变闷；
  - 只压 8 kHz 以上 12 dB "好很多，但是还有一些"；
  - 正经重采样（10–12 号）"三个都还有"。

这张票先修 bug，再在修好的基础上试后期高频处理，由用户挑。

做法起点：
- **修**：三处线性插值都换成带抗镜像滤波的重采样，对所有路线一样。
- **只重新挑选、混音，不重新合成**：原始候选（22.05 kHz）还在 `out/index/<版本>/<片段>/raw/`。
  - 小样用 `2.5-原声平均锚点新规`，〈2002〉用 `2.5-原声平均锚点全员`（〈2002〉里没有武也，两版一样）；
  - 剧本已带 18 号票的 `pause`，混出来要有停顿；
  - 挑中的候选要是变了，列出来。
- **高频处理给用户 A/B**：放在混音这一步，几版对比，比如：
  - 只修镜像，不另处理；
  - 只压 8 kHz 以上；
  - 缓的高频衰减（转折点、斜率试几档）。
  - 春希最明显，但要对所有角色一样。旁白和台词是否同样处理也要试。
- **试听材料**：
  - 先做一个短的 A/B 文件，春希为主，带时间表：`春希颤音AB.md` 那几句（小样 1、4、7、13 号，〈2002〉22、25、38 号）。用户戴 AirPods Pro 3 标颤音轻重，也听闷不闷；
  - 用户挑定后，再出小样和〈2002〉的整段 MP3 和对照剧本。
- **指标**：像原声、过音色门槛、认人、字错率。
  - 声纹和识别都在 16 kHz 上算，修镜像应该几乎不动，确认一下；
  - 削高频会不会让字错率上升，读音变糊。

要回答：
- 修完镜像，颤音轻了多少（试听）；
- 要不要后期高频处理，用哪一版、参数多少、代价（闷不闷、读音清不清楚）；
- 写进 `mix.py` 的默认值；旁白和台词是否一样。

## Answer

**修掉转 48 kHz 的镜像，混音时每句加一道缓的高频衰减（`mix.HIGHS_DEFAULT = "缓4k"`：一阶低通，4 kHz 起每倍频程 −6 dB），旁白和台词一样。** 用户戴 AirPods Pro 3 听 A/B："C或者D感觉会更好一些"，二选一定了 D；看了成品同意结票。

修镜像：
- 三处线性插值换成一个 `voices.to48k`（soxr HQ，带抗镜像滤波），所有路线都走它：
  - `bakeoff` 从 `voices` 导入，`cmd_index` 也改用它；
  - `TorchQwen.takes`、`qwen_takes`、VoxCPM、`index_passage.read_take` 都经它转。
- `voices.Pak.audio`：游戏原声抽查都是 48 kHz，原来那段插值实际走不到，照样换了。
- `soxr>=1.1.0` 写进 `pyproject.toml`，原来是 librosa 间接带进来的，`uv.lock` 只多这一项。
- 量出来（`books/wa2/trials/resample/镜像.md`）：
  - 成品 11–16 kHz 原来 −33～−37 dB，修后 −84～−88 dB，只剩噪声底；
  - 线性插值本身也是低通（sinc²），修前 4–11 kHz 被压暗 2–6 dB；修后和 22.05 kHz 原件各段差不到 0.3 dB。
- 修完镜像颤音轻了多少：A/B 里有修前（A）和只修镜像（B），用户没单独说。从挑了 C/D、没挑 B 看，光修镜像不够，IndexTTS-2.5 在 8 kHz 以下自带的那部分还在。

不重新合成，只重新挑选：
- `index_passage repick <版本> <片段>`：读这一版 `raw/` 的现成候选，用同样的规则挑选、混音，成品写到 `out/index/<版本>-重采样/<片段>/`。
  - qc.json 多记 `take`，挑中的是第几个候选；`bakeoff.finish` 的明细多一项 `pick`。
- 挑中的变了 1 句：小样 10 号春希心里话「………真是，两个本末倒置的家伙。」，0 号 → 1 号候选。
  - 0 号的音高估计 141.6 → 141.0 Hz，质检分 0.4498 → 0.4586，越过 0.45 线，于是多试了一个；
  - 〈2002〉58 句都没变。
  - 旧挑选是用旧插值加旧 qc.json 里的相似度复现的，`tries` 和 `score` 句句对上。

高频处理（`mix.HIGHS`，`mix.tame`）：
- 放在 `mix.process` 的最前面：先削高频再拉响度，几档响度一样。`passage.mix`、`passage.remix`、`mix.assemble` 都多了 `highs` 参数，不给就用默认。
- A/B（`out/resample/ab/高频AB.wav`，不进 git）放了六版，每句连着放：
  - A 修前；B 只修镜像；C 压8k（高架）；D 缓4k；E 缓2.5k；F 缓1.5k（用户在 Audacity 里做的那种）。
  - 句子：春希 7 句（小样 1、4、7、13，〈2002〉22、25、38），加雪菜、依绪各一句听闷不闷。
- 选 D 不选 C：颤音在 8 kHz 以下，D 在 4–6 kHz 压 3–5 dB，C 几乎不动；用户也没觉得 D 闷。
- 代价：缓4k 和只修镜像的指标一样（见下）。削得更狠才有代价：
  - 缓2.5k、缓1.5k 像原声再降 0.01–0.02；
  - 小样 81 号「雪菜…」被识别成「学菜」，"x"的擦音被削糊；
  - 缓1.5k 过门槛掉到 28/31。
- 旁白和台词一样：A/B 里两类都有，用户没分开提。按要求对所有角色一样。

指标（从成品 MP3 测，锚点同 17 号票，和按现剧本重混的修前比）：
- 小样：像原声中位 0.63 → 0.62，过门槛 30/31 不变，认人 100%，字错率中位 0.040 → 0.018；
- 〈2002〉：像原声中位 0.65 不变，过门槛 47/47，认人 100%，字错率中位 0.042 → 0.033；
- 声纹和识别都在 16 kHz 上算，修镜像几乎不动。
- 只修镜像时小样过门槛 29/31：差的是依绪 2 号，0.597 → 0.588，门槛 0.59，算噪声级。

没做的：
- 豆包（`volc_passage`）自己拼段落，不走 `mix.process`，没加高频处理。那条路线已暂停。
- 现有的 Qwen3 锚点 wav 里还带着镜像，没重做：IndexTTS 读参考时会重采样，不影响成品。

重做：

    uv run python -m readbook.index_passage repick 2.5-原声平均锚点新规 小样
    uv run python -m readbook.index_passage repick 2.5-原声平均锚点全员 "2010-11-25 〈2002〉"
    uv run python -m readbook.resample 镜像      # 修前修后各频段能量
    uv run python -m readbook.resample ab        # 高频处理 A/B
    uv run python -m readbook.resample 混音 缓4k  # 小样和〈2002〉的成品

产物在 `books/wa2/trials/resample/`：
- 小样和〈2002〉的 MP3、对照剧本、指标；
- `镜像.md`；
- `重采样和高频-对比.md`：各档指标、A/B 设计和用户原话。

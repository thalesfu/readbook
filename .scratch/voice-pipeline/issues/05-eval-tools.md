# 05: 评测工具补强

Type: task（AFK）
Status: resolved
Blocked by: 01

## Question

把评测从"和一条参考比"改成业界做法，后面所有原型都用它出指标：
- 声纹相似度改成和本人**原声的嵌入中心**比，同时保留和音色锚点比的数字；
- 不到 1.5 秒的句子单独统计；
- 每个角色的音色门槛取"本人真实原声两两相似度"分布的 P5；
- 加 emotion2vec+ 情感分类，出一张"情感 × 音色"二维表，看每种情绪下的相似度；
- 认人准确率、识别字错率、音高和语速范围沿用现有做法。

**完成标准**：一条命令对任意一个版本的小样或〈2002〉出完整指标表；在 Mac 混合版的现有音频上跑一遍，作为基线数字。

## Answer

完成标准已经达到。一条命令出完整指标表，输入可以是逐句 wav 目录，也可以是混好的 MP3：

```
uv run python -m readbook.evaluate 小样 <逐句 wav 目录或 MP3>
uv run python -m readbook.evaluate 2002 <逐句 wav 目录或 MP3>
```

结果写在输入旁边：`<版本>-指标.md` 是总表，`<版本>-指标-逐句.jsonl` 是逐句明细。每次大约 30 秒，含加载模型。Mac 混合版的基线已经跑完，放在 `books/wa2/baseline/`：`小样-混合版-指标.md`、`2010-11-25 〈2002〉-混合版-指标.md`。

**基线数字**（Mac 混合版，从 MP3 切回逐句；只算 ≥1.5 秒的句子）：

| | 句数 | 像原声 中位（最低） | 过音色门槛 | 像锚点 中位（最低） | 认人·锚点 | 认人·原声中心 | 字错率中位 / >0.3 | 句内变调 |
|---|---|---|---|---|---|---|---|---|
| 小样 | 29 | 0.56（0.23） | 21/29 | 0.79（0.16） | 26/29 | 27/29 | 0 / 4 句 | 4 句 |
| 〈2002〉 | 44 | 0.54（0.13） | 35/44 | 0.63（0.14） | 36/44 | 40/44 | 0 / 3 句 | 0 |

- 认人准确率算上短句：小样按锚点 36/43、按原声中心 40/43；〈2002〉分别是 44/58、51/58。
- 分角色看，最弱的是春希：小样里春希台词 5 句只有 1 句过门槛（像原声中位 0.39）；〈2002〉春希旁白和心里话 31 句里 8 句没过（0.13–0.41）。技术报告里也说过〈2002〉春希有 8 句旁白只有 0.13–0.30，但那次的参考音不一样，没有逐句核对是不是同一批。雪菜、武也的长句都过了，依绪只有两句兴奋没过（0.50、0.57）。
- 字错率超过 0.3 的 7 句里，6 句是同音字：4 句是人名（"依绪"→"一叙"、"雪菜"→"学菜"），另外两句是"转部"→"转步"、"呐"→"那"；还有 1 句是结巴重复的字没被识别出来。看识别结果都不像读错，但没有逐句去听。
- 音高、语速、逐句明细和两张"情感 × 音色"表见两份指标文件。

**做了什么**：
- **`readbook/evaluate.py`**：新的评测命令。
  - 像原声：和本人日语原声的嵌入中心比。原声从语音包里按固定种子随机取 300 句（1.5–15 秒），向量缓存在 `out/eval/real.npz`。
  - 像锚点：和音色锚点（`books/wa2/voices/<名字>/平常.wav`）比，保留下来对照以前的数字。
  - 音色门槛：见下面的用户决定。
  - 短句：去掉首尾静音后不到 1.5 秒的句子单列，不进主表。
  - 认人准确率：照旧按锚点算，另附按原声中心算的。
  - 情感 × 音色：emotion2vec+ large 给每句识别情绪，出"情绪 × 角色"表，格子里是像原声的中位数；另附一张按剧本标注情绪分的。
  - 字错率、音高和语速范围、句内变调沿用以前的做法。春希的旁白和心里话（讲述模式）单列一组。
- **能评混好的 MP3**：`mix.assemble` 在句间插的是纯零，长度已知，所以能按纯零切回逐句。长句里的停顿有时也是纯零，所以再拿对照剧本的时间戳估每句多长，用动态规划挑句界。在〈2002〉上 58 个句界和对照剧本逐句对上（差的都是句子自带的开头静音）；小样的对照剧本是锚点版的，时间对不上，但切出来的每句字错率都正常。小样指标文件里的逐句表带着混合版的真实时间戳，可以代替原来那份锚点版的对照剧本用。
- **CAM++ 搬进 readbook 环境**（用户定的）：Windows 上 `readbook/speaker.py` 在本进程里用 GPU 算，权重和 IndexTTS2 是同一份（HuggingFace 的 `funasr/campplus`），特征提取和原来的 worker 一样。Mac 上还走 IndexTTS2 的子进程，没动。
- **Whisper 换 PyTorch 版**：`readbook/asrcheck.py` 在 Windows 上用 transformers 跑 `openai/whisper-large-v3-turbo`（fp16，GPU），参数和 mlx 版一样（温度 0、同一句提示）。Mac 上不变。
- **依赖**：Windows 上加了 funasr（emotion2vec+、CAM++ 的模型代码）和 transformers。Mac 锁定的版本一个都没变。
- **模型**：`config.hf_model()` 先找缓存，缓存里有就不联网；`config.py` 默认走 hf-mirror、关掉 xet。三个模型（CAM++ 28MB、Whisper 1.6GB、emotion2vec+ 1.9GB）都已经下到 `~/.cache/huggingface/hub`。
- **证书的做法改了**：pip-system-certs 注入的是 pip 自带的那份 truststore，huggingface_hub 2.x 自己又用独立的 truststore，两份叠在一起一联网就 `RecursionError`。所以 readbook 去掉了 pip-system-certs，改成在 `config.py` 里调用 `truststore.inject_into_ssl()`。实测 requests、huggingface_hub、urllib 都能过 Norton。"Norton 不动，每个环境改用 Windows 证书库"这个决定没变。运行环境文档已经更新，包括以后建 IndexTTS2、Applio 环境时该怎么选。
- `mix.py` 把句间间隔抽成 `gap()`，切分时用同一套规则。

**用户定的两件事**：
- CAM++ 直接搬进 readbook 的环境，不等 IndexTTS2。
- **音色门槛用中心尺度 P5**：每句原声和其余原声中心的相似度，取 P5。它和"合成句像原声中心"是同一个尺度。现在的值：春希 0.45、雪菜 0.40、依绪 0.59、武也 0.55。票上原来写的"原声两两相似度的 P5"只有 0.18–0.37，和逐句分数不在一个尺度上，指标文件里只作参考。术语表里"音色门槛"的定义跟着改了。

**顺带发现的**：
- 真实原声之间没有以前以为的那么像：两两相似度中位只有 0.53–0.62，和原声中心比是 0.75–0.80。以前说的"同一个人 0.7–0.8"是合成句和锚点比出来的。
- 同性别角色的原声中心彼此很近（春希–武也 0.72，雪菜–依绪 0.70），但按原声中心认人，真实原声上仍有 96–99.7% 准，可以当参照。
- emotion2vec+ 的输出几乎都是独热的（最高一类接近 1），在这批合成音上标签也偏粗：春希的平常定妆音被判成"生气"。只用来看趋势。有一个趋势值得注意：〈2002〉春希的旁白里，被听成"开心"的 4 句像原声中位只有 0.27，"中立"的 24 句是 0.58，也就是说音色漂了的句子，听起来情绪也变了。

**留给 06 号票**：
- 基线是从**混好的 MP3** 算的，带着房间感、回忆、内心处理这些效果。06 要拿自己混好的 MP3 用同一条命令再跑一遍，这样才能和基线公平比；逐句干声的数字另算，不要和基线直接比。
- 切 MP3 要有带时间戳的对照剧本。`passage.py` 写出的就是对的，放在同一目录、名字共同前缀最长就会被自动找到；也可以作为第三个参数传进去。

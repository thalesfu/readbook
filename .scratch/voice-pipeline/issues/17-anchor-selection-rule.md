# 17: 音色锚点的挑选规则补上门槛和音高抖动

Type: prototype（HITL）
Status: resolved
Blocked by: 16

## Question

16 号票定了四人都用原声平均锚点当 IndexTTS-2.5 的说话人参考（全员版），试听和数据留下三个和锚点有关的问题：
- **春希讲述有合成颤音**：新春希锚点本身的音高抖动 85 音分，旧锚点只有 13；〈2002〉春希讲述句的抖动中位从 66 涨到 106。候选 1 像原声 0.76，抖动 37，只有现在这个的一半左右。
- **武也的锚点本身没过音色门槛**：挑中的新锚点像原声 0.53，他的门槛是 0.55。成品小样 3 号像原声 0.44，没过门槛。
- **雪菜音高偏高**：成品 311–320 Hz，原声约 300；读错的句子比 10 号票多两三句。

现在的挑选规则（`readbook/rawanchor.py`）只拦读错和质检不过（时长、句内变调、音高语速离原声目标太远），剩下的取像原声最高的。这张票把规则补全，对所有角色一样，不按人特调：
- 锚点本身要过本人的音色门槛；
- 音高抖动设上限，上限从本人原声的分布里取（比如不高于原声的某个分位），不手填；
- 音高离原声目标的容差要不要收紧，看雪菜的情况决定。

所有候选都不合格时怎么办（多生成几个候选、退回旧定妆音，或者别的办法），先列出做法给用户选。

按新规则重挑锚点。有角色的锚点变了，就重做 IndexTTS-2.5 的小样和〈2002〉，情感参考和情感向量照 16 号票不变。和 16 号票的全员版（`books/wa2/trials/rawavg-anchor/*-IndexTTS-2.5-原声平均锚点全员.*`）比：
- 春希的颤音还在不在：音高抖动加上试听；
- 武也那句过没过门槛；雪菜的音高和读错；
- 整体像原声、过音色门槛、认人准确率；
- 情绪是否仍然到位（试听）。

句子级的重试（比如依绪小样 62 号 0.57 没过门槛）不在这张票里，留给 15 号票定质检和重试规则。

## Answer

**定论：锚点的挑选规则补上音色门槛和音高范围，不加音高抖动上限**（定版）。用户试听后定的："先结 17 号票"。完整数据见 `books/wa2/trials/anchor-rule/锚点挑选规则-对比.md`。

- **定版规则**（`readbook/rawanchor.py`，对所有角色一样，数都从本人那批 300 句原声的分布来，不手填）：
  - 没读错；
  - 过质检；
  - **音高离目标不超过本人原声音高四分位距的一半**（新）；
  - **像原声过本人的音色门槛**（新，P5）。
  - 合格的取像原声最高的。
  - **都不合格**（用户选的）：换种子再生成一批 8 个，最多 4 批，有合格的就停；还没有，就放宽质检和音高，在没读错、过门槛的里面取像原声最高的。
- **挑出来的**：
  - 春希、雪菜、依绪和 16 号票全员版是同一个锚点；
  - 武也 7 号 → 14 号（第 2 批）：像原声 0.53 → 0.66，过了门槛；161 Hz（原声 144）。
- **成品**：
  - 〈2002〉里没有武也，和全员版完全一样；
  - 小样只有武也那句不同：像原声 0.44 → 0.62，过门槛 29/31 → 30/31，认人 100%；
  - 同一句同一种子的候选：武也 0.45 → 0.59，过门槛 0/4 → 3/4。
  - 版本 `2.5-原声平均锚点新规`。
- **音高容差：对雪菜不用收紧，对武也要收紧**：
  - 雪菜锚点 308 Hz 比目标高 4%，还在她原声的正常范围（276–320）里，音高和读错都和全员版一样。读错归 15 号票的句子级重试；
  - 武也：质检是音高、语速合起来打分，语速贴目标时音高高两成也能过（多生成的 18 号 176 Hz）。锚点的音高会带进成品，所以加了第 3 条。
- **音高抖动上限试过（试版），去掉了**：
  - 照票的要求，上限取本人原声的中位，算法是 16 号票的（音高曲线减 0.3 秒滑动平均，`qc.jitter`）。春希因此从 0 号换成 1 号（85 → 37 音分）；
  - 用户试听"电子的颤音"还在。A/B 里锚点本身的颤音听感是旧定妆音"中"、0 号"无"、1 号"轻"，和抖动数（13、85、37）正好排反。成品 7 句平均：10 号票 2.9、全员 1.7、试版 2.1；
  - 拿这 24 段试了十种别的量法，没有一种排得对三个锚点。这种颤音眼下只能靠听；
  - 试版的锚点和产物留在 `锚点-试版/`、`*-原声平均锚点新规试版.*`。
- **用户听到的电子颤音，查下来有两部分**，都不归锚点挑选管：
  - **转 48 kHz 的镜像**：我们自己的 bug。`bakeoff.to48k` 用线性插值把 IndexTTS 的 22.05 kHz 输出转成 48 kHz，11 kHz 以上多出一层镜像，成品 12–16 kHz 有 −33 dB。去掉能轻一些，不用重新生成，重新挑选、混音就行；
  - **IndexTTS-2.5 原始输出自带的**：在 8 kHz 以下，正经重采样、再去掉 8 kHz 以上都还在。缓的高频衰减（1500 Hz 起每倍频程 −6 dB）能让它轻一些，代价是声音变闷。锚点影响它的轻重（0 号最轻）。
  - 戴 AirPods 明显，笔记本扬声器上好很多。
  - 试听材料在 `out/rawanchor/ab/`（不进 git）。
- **顺手发现的**：
  - 小样 73 号「～～～呃！？」：句首的「～～～」原样送进 IndexTTS，读出一个「克」，是文本规整的问题；
  - 对照剧本的时间会出现 "4:60.0"（`passage.py` 秒数进位）。
- **代码**：
  - `qc.jitter`（16 号票的抖动算法，留着，注明对不上听感）；
  - `evaluate.real_clips` / `real_pitch`（和音色门槛同一批原声）；
  - `rawanchor` 的定版规则和 `report17`，`index_passage` 的 `2.5-原声平均锚点新规` 版。
  - 命令 `uv run python -m readbook.rawanchor`、`uv run python -m readbook.index_passage 2.5-原声平均锚点新规 小样`。

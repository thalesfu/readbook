# 小说转有声书技术报告

截至 2026-10-26 的阶段总结：做到了哪一步、技术方案是什么、还卡在哪、接下来可以试什么。决策过程见 [小说转有声书方案](小说转有声书方案.md)，第一轮试做的数据见 [小说转有声书试做结果](小说转有声书试做结果.md)。

## 一、目标与现状

**目标**：把中文小说自动做成多角色有声书（MP3）：
- 每个角色一个贴合性格、前后稳定的声音，另有旁白；
- 区分台词和心理活动；
- 只给自己听。测试素材是《白色相簿2 剧本全集》（168 万字），角色声音尽量接近原作日语声优。

**现状**：
- 整条流水线已经跑通：剧本化 → 参考音 → 逐句合成 → 质检 → 混音 → MP3。
- 跑过两段完整试做（A：2011-01-01，157 句；B：2013-01-26，102 句），四轮约 3 分钟的小样对比，以及一段正式片段（2010-11-25〈2002〉，65 句）。
- 试听认可的配置是"混合版"。但**同一角色的音色仍会在某些句子上变化**，这是当前最大的问题。

## 二、当前技术方案

### 流水线

| 环节 | 做法 | 工具 |
| --- | --- | --- |
| 取文本 | 《白色相簿2》直接读游戏剧本：每句自带说话人、语音文件、日文原文。普通小说走 epub 解析。 | `readbook/wa2.py`，复用 gameresource 仓库的 `lscr` / `daily` / `lacpak` |
| 剧本化 | LLM 逐章给每句标：类别（旁白／台词／心理活动）、说话人、效果（无／电话／回忆／书信短信）、情绪（10 种）、表演提示 | `claude -p` 加 JSON schema，`readbook/scriptize.py` |
| 参考音 | 从游戏日语原声挑音高、语速居中的几句（10–18 秒）→ VoxCPM2 加说话风格生成中文"定妆音"，多个候选里挑最贴原声的一段 | VoxCPM2（MLX）、`readbook/bakeoff.py` |
| 逐句合成 | 以定妆音为参考做带文本复刻，温度 0.6 | Qwen3-TTS-12Hz-1.7B-Base（Mac 上 MLX；Windows 上官方 PyTorch 版，参数对齐方法见运行环境文档） |
| 质检 | 音高、语速、句内变调（半秒一段）超标就重做，最多 5 次取最好；语速拉回目标的 0.85–1.2 倍；音色用 CAM++ 相似度当门槛 | `readbook/qc.py`、`readbook/speaker.py`（CAM++ 跑在 IndexTTS2 的环境里） |
| 混音 | 心理活动加内心处理；电话、回忆分别加带通、混响；台词按角色左右定位并带一点房间感，旁白干声居中 | `readbook/mix.py`（scipy） |
| 输出 | 每章一个 MP3，44.1kHz、160kbps 联合立体声，带 ID3 和封面，另附对照剧本（时间戳、说话人、情绪） | ffmpeg |

### 试听认可的配置（混合版）

- 春希：分情绪版的定妆音，旁白和心里话用单独的"讲述"定妆音。
- 雪菜：低温版的单一锚点，不分情绪。
- 依绪、武也：锚点版，即一个音色锚点，情绪定妆音从锚点派生，过了 CAM++ 门槛才用。

### 关键数字

- 合成速度：VoxCPM2 实时率 1.17–1.9，Qwen3 和它相近，全书约 5–10 天；IndexTTS2 在 Mac 上实时率 50.8，不可用。
- 5090 实测（06 号票，混合版配置，含重试和质检）：合成耗时约为成品音频的 2.0 倍，每字 0.49 秒，全书 168 万字约 230 小时（9.6 天），还没到"一周内"。
- 5090 实测 IndexTTS（10 号票，每句最多 4 个候选，过关就停）：2.5 bf16 单个候选实时率约 0.8，合成耗时约为成品音频的 1.7 倍，每字 0.44 秒，全书约 205 小时（8.5 天）；2.0 fp32 每字 0.82 秒，约 16 天。
- 读音：识别字错率中位数为 0，正常句子基本没有读错。
- 盲测说话人准确率：93.0%，opus 93.6%，目标是 95%。

## 三、迭代过程

| 轮次 | 做法 | 结果 |
| --- | --- | --- |
| 第一轮整段 | VoxCPM2 逐句拿日语原声直接复刻；出三版：后期内心处理、指令内心处理、逐句原声做情绪提示 | 能听懂；但语气对不上性格、分不清是谁、同一人前后不一致。逐句原声版带日语口音，不可行。 |
| 小样一 | 改成先做中文定妆音，再对比 VoxCPM2 和 Qwen3 | 春希音高范围从 114–248 Hz 收窄到 132–179 Hz。Qwen3 版最好。 |
| 小样二 | Qwen3 温度从 0.9 降到 0.6，加句内变调检查 | 春希的平均音高回到原声的 165 Hz。依绪 #56、#58（兴奋大喊）仍不像她，音高冲到 296 Hz。 |
| 小样三 | 分情绪定妆音：每种情绪从对应情绪的日语原声各自独立做一段 | 失败：依绪、雪菜"每个人都很分裂"。CAM++ 测出雪菜的哭腔、惊讶、轻声定妆音和她本人只有 0.36–0.45，比依绪和雪菜之间（0.53）还低。 |
| 小样四 | 改成音色锚点：情绪定妆音从锚点派生，CAM++ ≥0.75 才用；逐句 CAM++ ≥0.65 | 认人准确率回到 41/43，依绪最稳。但锚点是按"CAM++ 最像原声"挑的，春希挑到一段语速偏快的，合成后放慢最多 38%，听着"很生硬"。 |
| 混合版 | 按试听结果，每个角色用效果最好的那一版 | 认可："这一版还不错"。 |
| 正式片段〈2002〉 | 按混合版配置做 65 句 | 仍有音色变化。春希有 8 句旁白和本人原声的相似度只有 0.13–0.30。 |
| 5090 复现（06 号票） | 换成官方 PyTorch 版 Qwen3-TTS，参数对齐 mlx-audio，重做小样和〈2002〉 | 第一版雪菜一半候选跑偏，原因是语音编码器被转成了 bf16，改回 fp32 后复现。试听"基本等同"，整体略好；问题句位置相同，但更明显。 |

## 四、当前问题与原因

### 1. 同一角色的音色在部分句子上变化（最主要）

- **现象**：〈2002〉里春希每句和本人日语原声的相似度中位数是 0.66，但最低到 0.13；雪菜在 0.33–0.61 之间。
- **原因**：
  - **零样本复刻本身就有随机性**：每一句都是模型拿参考音现场重新"猜"一遍这个人的声音，没有任何跨句约束。温度、句子长短、情绪强弱都会影响它猜得准不准。重试加质检只能压低出错的比例，消除不了。
  - **参考音是合成出来的**：定妆音本身就是 VoxCPM2 生成的，和原声的相似度只有 0.63–0.81。逐句复刻等于在复刻一份复制品，误差会叠加。
  - **一个角色有多段参考音**：春希分情绪版的"平常"和"轻声"两段定妆音之间只有 0.41，切换参考音就会跳音色。
  - **质检不一致**：春希用的分情绪版配置没开 CAM++ 门槛，漂了的句子没拦下来。

### 2. 情绪和音色绑在一起

- **现象**：Qwen3 复刻模式不接受情绪指令，情绪只能靠换参考音来带，而一换参考音就容易"像换了个人"。
- **原因**：Qwen3 只有一个参考输入，音色和情绪都从这一个输入里来，模型结构上就没有把两者分开。

### 3. 语气生硬、和性格对不上

- **原因**：
  - **语速被大幅修正**：锚点语速偏快时，合成结果要被放慢很多，变速一大声音就发僵。Qwen3 复刻模式不支持直接调语速。
  - **质检把表现力也压掉了**：挑候选时偏向"音高和语速最接近平均值"的那一个，等于在挑最平淡的。
  - **性格信息进不去**：说话风格只在生成定妆音时用了一次，逐句合成时模型拿不到任何"这个人平时怎么说话"的信息。

### 4. 角色之间的区分度

- 依绪和雪菜是最接近的一对（CAM++ 0.53）。锚点版做了拉开，但在不分情绪的配置下，两人仍可能混。

### 5. 说话人判断（通用小说那半边）

- 盲测 93.0%，没到 95%。错在原文本身信息不足的句子：没有署名的回忆台词、群戏里的"啊…""呃…"、没有前后文交代的独白。换更强的模型也只多对一句。

### 6. 工程上的限制

- IndexTTS2 只针对 CUDA 优化，在 Mac 上跑不动（实时率 50.8，还会因内存被系统杀掉），要用就得放到 5090 笔记本上。
- Qwen3-TTS 在 MLX 复刻模式下不支持 `speed` 参数。
- mlx-audio 的 Whisper 偶尔会在一句上死循环，已经改成子进程、每句限时。

## 五、业界进展

调研范围是 2025–2026 年的论文、官方仓库和文档，链接都在原文里。标"（推测）"的是调研代理或我的判断，其余是一手来源写明的内容。个别新论文只看了摘要，数字没有逐一核实。

### 1. 怎么把音色彻底稳定住

**总体判断**：业界能把音色锁死的做法，都是把音色固化进模型权重，有两条路：按角色训练声音转换（VC）模型做后处理，或按角色微调 TTS。零样本复刻上的技巧只能减轻漂移。长篇合成里的说话人漂移已经有专门研究，比如 DiTAR+ 发现基线大约生成 15–18 秒后相似度明显下降，MagpieTTS-LF 用跨块的状态传递来缓解。

**声音转换做后处理**
- **RVC（及分支 Applio）**：用内容特征加检索，只换音色，音高和节奏沿用输入，所以 TTS 生成的情绪基本能保留。约 10 分钟干净数据就能训，支持 50 系显卡（cu128），MIT 协议，仓库 2026-08 仍有更新；Applio 已进入维护模式。（[RVC](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI)）
  - 已知风险：尖叫、哭腔、气声处容易出伪影；男女之间要手动移调；清晰度会小幅下降。
- **VC 会损失多少清晰度**：Seed-VC 的官方评测有量化数据：原音 WER 8.02，经 Seed-VC 后 11.99，OpenVoice 15.46，CosyVoice-VC 18.98。（[EVAL](https://github.com/Plachtaa/seed-vc/blob/main/EVAL.md)）Seed-VC 本身已于 2025-11 归档，GPL 协议。
- **新模型**：MeanVC（流式零样本，Apache）、X-VC（2026，称跨语种相似度强，没给数字）、OneVoice（报告相似度和韵律之间有取舍）。

**按角色微调 TTS**
- **VoxCPM2**：官方支持全参微调和 LoRA，LoRA 可以热切换，适合多角色。单说话人 5–50 条起，LoRA 训 1–3 轮，显存约 20GB（全参约 40GB）；r=32 的 LoRA 相似度约为全参的 98%。加新语言时，建议混入 10–20% 原有语言的数据防遗忘。（[微调文档](https://voxcpm.readthedocs.io/en/latest/finetuning/finetune.html)）
- **Qwen3-TTS**：官方有单说话人 SFT 脚本。论文称只用单语数据微调，也能跨语言迁移音色，日→中跨语种字错率 3.43%。（[论文](https://arxiv.org/abs/2601.15621)、[微调脚本](https://github.com/QwenLM/Qwen3-TTS/tree/main/finetuning)）已知坑不少：越训语速越快、标签对齐的修复没合并、Windows 上写死了 flash-attention、说话人编码器权重会被衰减。mlx-audio 只能推理，不能训练。
- **GPT-SoVITS**：做动漫角色的社区里最成熟，MIT 协议，2026-10 出了 v5；Seed-TTS 中文集上的相似度 v5turbo 0.783、真人 0.755。（[wiki](https://github.com/RVC-Boss/GPT-SoVITS/wiki)）
  - **关键坑**：官方写明，微调数据大且只有日语时，跨语种能力会被洗掉，所以微调集要控制在 30 分钟以内或混入中文。Mac 上训练出来的质量明显偏低。
- **其他**：Fish Audio Drama 3（2026-10，主打多角色广播剧和多参考克隆，开放权重，35B-A3B，5090 笔记本能不能跑没有核实）；F5-TTS 权重是非商用协议，且 2025-03 后没更新。

**零样本复刻的一致性技巧**
- Qwen3-TTS 有两种克隆方式：只用说话人嵌入（官方说质量可能下降），或参考音频加参考文本（论文称更能保留韵律）。
- 参考音频越长相似度越高，大约到 10 秒饱和。
- 我们的定妆音本身就是 VoxCPM2 合成的，等于"复刻的复刻"，误差会叠加（推测）。

### 2. 怎么在不破坏音色的前提下控制情绪

- **IndexTTS2 / 2.5**：音色参考和情感参考可以来自不同的人。情感有三种给法：一段参考音频、8 维情感向量（喜、怒、哀、惧、厌恶、忧郁、惊讶、平静），或一段文字描述。训练时专门用梯度反转把音色和情感拆开。（[论文](https://arxiv.org/html/2506.21619v2)、[仓库](https://github.com/index-tts/index-tts)）
  - **量化数据**：论文里说话人相似度 0.836、情感相似度 0.887、情感 MOS 4.22，CosyVoice2 分别是 0.803 / 0.802 / 3.09。是调研里唯一同时报告"情感 + 音色"两项指标的开源模型。
  - **速度**：2.5 版语义码帧率降到 25Hz，支持中、英、日、西，RTX 4090 上实时率 0.21（2.0 fp16 是 0.33）。5090 笔记本大约是台式 4080 的水平，预计实时率 0.3–0.5（推测）。
  - **风险**：第三方 DisCo-Speech 的听测指出，情绪强时会出现音色泄漏；官方也建议情感强度不超过 0.6 左右。
- **VoxCPM2 可控克隆**：参考音频定音色，文本前加括号指令控情绪、语速。技术报告里没有这个模式下的音色或情感量化数据，还承认中文抽象指令跟得较弱。
- **Qwen3-TTS**：只有预置音色版和音色设计版支持指令，复刻用的 Base 版没有。"复刻音色加指令控情绪"这条路在 Qwen3 上目前走不通。
- **Step-Audio-EditX（阶跃，2025-11）**：对已经生成的音频做情绪和风格编辑，可以多轮迭代，中文情感准确率从 58.7 提到 77.8。论文没报告编辑后的说话人相似度。
- **商用**：MiniMax 有 9 种情绪参数；ElevenLabs v3 用 `[crying]` 这类音频标签；Fish Audio S2 支持自由文本标签；豆包声音复刻 2.0 号称"保留声线的同时增加情感演绎"，只找到媒体报道。

### 3. 长篇多角色有声书系统

- **Audiobook-CC（喜马拉雅）**：旁白和对白分开处理，旁白结合前后文生成，对白用情感指令生成。章节级 MOS 4.25，CosyVoice2 是 3.88。（[论文](https://arxiv.org/html/2509.17516v1)）
  - 一个有用的发现：参考音和目标音来自同一段录音时，说话人相似度能到 0.87，但参考音的韵律会漏进来；两者分开后相似度降到 0.69–0.79，听感反而更好。也就是说，**相似度不是越高越好**，这和我们"按 CAM++ 最像来挑锚点反而生硬"的经验一致。
- **Deep Dubbing**：由 LLM 给每句写"单句情感 | 上下文场景 | 文本"格式的指令，情感 MOS 从 3.67 提到 4.15，字错率基本不变。
- **MultiActor-Audiobook**：根据人物描述生成人脸，再用"人脸→声音"模型选音色；由 GPT-4o 给每句写情感、语气和音高指令。
- **MOSS-TTSD、FireRedTTS-2、MoonCast**：偏播客、对谈，不适合"旁白 + 心理活动 + 多角色"的剧本（推测）。
- **豆包"AI 多人有声剧"**：已在番茄小说上线，称角色划分准确率 98% 以上，只见于媒体。

### 4. 说话人判断（通用小说那半边）

- **LLM 整章联合判断**：Llama-3-8B 把整章切成 4K token 的块，所有台词一起判断，提供角色别名表，后面的块回头修正前面的结果。英文小说语料上"没有显式署名"的台词从 68.9% 提到 89.1%。（[论文](https://arxiv.org/html/2406.11380v3)）
- **编码器联合打分（2026-08）**：同一语料上 94.5%，速度是 LLM 方法的上千倍，开源了 ModernBookNLP，只支持英文。
- **中文**：WP 数据集上 GPT-3.5 准确率 83.8%。

### 5. 评测

- **业界常用指标**：
  - 字错率：Seed-TTS-eval 的做法，中文用 Paraformer 识别；
  - 说话人相似度：WavLM 或 CAM++ 一类的声纹模型，中文真人句子之间约 0.76–0.78；
  - 情感分类：emotion2vec+（9 类）；
  - 主观分：MOS。
- **免参考的自动打分**：Audiobox Aesthetics（Meta），以及用音频大模型当评委（EmergentTTS-Eval、Gemini 2.5 Pro）。
- **对我们指标的改进建议**：
  - 和角色"真实原声的嵌入中心"比，不要只和一条参考比；
  - 不到 1.5 秒的句子单独统计，因为声纹模型在短句上测不准；
  - 阈值用自己的数据定：取同一角色真实原声之间相似度分布的 P5 当下限。

## 六、可以做的尝试

按"先便宜后昂贵"排列。每一项都在同一段小样（加上〈2002〉）上和混合版对比，用第七节的方法评估。

### A. 在 Mac 上马上能做（各约半天到一天）

| # | 尝试 | 要解决的问题 | 依据与风险 |
| --- | --- | --- | --- |
| A1 | Qwen3 **直接拿日语原声做参考**（参考音频加日文逐字稿），去掉定妆音这层复制 | 音色漂移、"复刻的复刻" | Qwen3 论文日→中字错率 3.43%。风险是带出日语口音，要用识别字错率加试听验证。 |

## 七、评估方法

每次改动都在小样和〈2002〉上对比，以下几项一起看。一条命令出全部指标（05 号票补的）：

```
uv run python -m readbook.evaluate 小样 <逐句 wav 目录或混好的 MP3>
uv run python -m readbook.evaluate 2002 <逐句 wav 目录或混好的 MP3>
```

- **音色一致性**：CAM++ 相似度，看中位数和最低值。
  - **像原声**（主数字）：和本人日语原声的嵌入中心比。原声从语音包里按固定种子随机取 300 句（1.5–15 秒）。
  - **像锚点**：和音色锚点比，保留下来方便和以前的数字对照。
  - 早先说的"同一个人 0.7–0.8"是合成句和锚点比的结果。真实原声之间其实没那么高：两两相似度的中位数只有 0.53–0.62，和原声中心比的中位数是 0.75–0.80。
- **音色门槛**：每个角色取"每句原声和其余原声中心的相似度"的 P5，和"像原声"是同一个尺度。现在的值：春希 0.45、雪菜 0.40、依绪 0.59、武也 0.55。原声两两相似度的 P5 只有 0.18–0.37，不在一个尺度上，只作参考。
- **短句单列**：去掉首尾静音后不到 1.5 秒的句子，声纹测不准，单独统计，不进主表。
- **认人准确率**：每句离哪个角色的锚点最近，看是不是本人；另附按原声中心算的。真实原声按原声中心认人有 96–99.7% 准，可以当参照。
- **情感 × 音色**：emotion2vec+ large 给每句识别情绪，列出每种情绪下的"像原声"中位数；另附按剧本标注情绪分的表。emotion2vec+ 的输出几乎都是独热的（最高一类接近 1），在这批合成音上标签也偏粗，只用来看趋势。
- **读音**：Whisper large-v3-turbo（Windows 上用 PyTorch 版）识别回文字算字错率。人名常被识别成同音字（"依绪"→"一叙"），所以字错率高的句子要人听。
- **音高、语速、句内变调**：音高中位数和 10%–90% 范围，语速范围，句内跳变超过 1.45 倍的句数。
- **试听**：最终以耳朵为准。CAM++ 只当门槛用；拿它去挑"最像"的，反而挑出了生硬的锚点。
- **混好的 MP3 也能评**：按句间的纯零静音切回逐句，切出来的句子带着混音效果，所以 MP3 的数字只和 MP3 比。Mac 混合版的基线就是这样从 MP3 算出来的，见 `books/wa2/baseline/*-指标.md`。

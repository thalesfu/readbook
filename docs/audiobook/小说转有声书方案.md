# 小说转有声书方案

要把中文小说自动做成多角色有声书（MP3）：每个角色配上贴合性格的固定音色，另外有旁白，还要区分台词和心理活动。先把方案想清楚，再拿《白色相簿2 剧本全集》挑片段试做。

> 正式合成流程以 [小说转有声书合成规格](小说转有声书合成规格.md) 为准（2026-10-30）。下面"已定"里的引擎路线、音色流程是早期的做法，留作决策记录。

## 已定

**适用范围**：面向通用中文小说，由 LLM 判断每句话是谁说的，并分出台词、心理活动和旁白。原文本身带结构标记的书走解析捷径，不经过 LLM。

**测试素材**：《白色相簿2 剧本全集》epub，位于 Calibre 书库的 `九户史明/白色相簿2 剧本全集 (2528)/`。全书约 168 万字，共 255 个章节文件。

**测试素材的结构标记**：
- `<strong>名字</strong>：「…」` 是有名字的台词，约 4.6 万句，涉及 231 个说话人名。
- `<em>…</em>` 是春希的第一人称叙述，约 2.3 万段、62 万字。
- 不带名字的 `「…」` 是春希的台词，只出现在序章，共 29 句。
- `『…』` 约 1500 段，其中 338 段带名字。带名字的多是用眼神交流（没说出口）；不带名字的混着几种情况：春希想说却没说出口的话、回忆里别人说过的话、电话、邮件和书信。
- 另有 151 处注音（ruby），以及 `？？？` 这种身份暂时不明的说话人。
- 同一个人有多种写法，例如 依绪／依緒、美穰子／美穂子、雪菜母亲／雪菜的母亲。

**白色相簿2 的数据源**：结构捷径直接读游戏导出的数据（`lscr.py` 的 JSON 加语音对照表），不解析 epub。每句台词都自带说话人、语音文件和日文原文：
- `？？？` 是谁，看语音的角色编号就知道；
- 日文原文当复刻参考音频的逐字稿用。

epub 解析留给普通小说；盲测仍然拿 epub 去掉名字来跑。

**素材的第二个用途**：《白色相簿2》的结构标记可以当标准答案，用来检验 LLM 判断说话人的准确率。

**用途**：只给自己听，不公开分发。允许复刻原作声优的声音。协议明令禁止模仿真人的引擎不用，例如 Fish Speech／OpenAudio。

**引擎路线**：正式合成全部在 Mac 本地完成，Qwen3-TTS（通过 mlx-audio）负责按文字描述设计音色，VoxCPM2（MPS）负责复刻音色和逐句合成。测试阶段另用豆包语音 2.0 的预置音色合成同一片段，做 A/B 对比。

**文本的三个类别**：
- **旁白**是叙述者的讲述。第三人称小说用独立的旁白音色；第一人称小说的叙述者就是主角，用主角音色，但要做成明显不同的"讲述模式"：
  - 单独做一段讲述定妆音，平静、低缓，像在回忆；
  - 混音时旁白用干声、贴耳、稍轻；台词带一点房间感，主角的台词稍微偏离正中。
  - 心理活动也用讲述定妆音，再加内心处理。
- **台词**是说出口的话，用说话人的音色。
- **心理活动**是某个角色没说出口的想法，用这个角色的音色，再加内心处理。

《白色相簿2》的 `<em>` 要由 LLM 再分成讲述（归旁白）和心里话（归心理活动）。

**声音效果**：每句话除了类别，还单独标一个效果，先定四种：
- `无`
- `电话`：窄频 EQ
- `回忆`：轻混响，听起来稍远
- `书信短信`：干声朗读，不加效果

`『』` 属于哪种类别和效果、是谁说的，由 LLM 判断。例如：
- 用眼神交流 = 台词，加内心处理
- 春希想说却没说出口的话 = 心理活动
- 回忆里别人说过的话 = 那个人的台词，加回忆效果

**角色分三档配音色**（按合并写法后的台词句数）：
- **主要角色**（≥500 句，11 人，占台词的 92%）：每人一个专属音色。有原作声优素材的复刻，没有的设计。
- **配角**（30–499 句，28 人）：有自己语音编号的（`00`–`37`）一律复刻，没有的设计一个专属音色。
- **龙套**（<30 句，188 人）：包括 `98`／`99` 这两个多人共用的编号。由 LLM 判断性别和年龄，再从一个约 10 个音色的公共池里分配，同一个名字全书固定一个音色。
- 语音编号对应的是声优，不是角色。有少数编号一人配了两个角色，比如 `28` 是和希和吉田，`04` 是千晶以及她在剧中演的雪音、榛名。复刻时按编号取参考音频，这几个角色就会是同一个声音，和原作一致。
- `？？？` 由 LLM 根据上下文判断实际是谁。

**复刻素材**：从本机游戏的语音包里提取，路径 `~/Windows/games/WHITE ALBUM2_Chs/VOICE.PAK`，是 2011 年的 PC 版。
- 格式是 LAC：文件头之后是 38736 条索引，每条 40 字节，前 32 字节是文件名（按位异或 0xFF 后得到原名），后面分别是大小和偏移。内容是 OGG。
- 文件名形如 `1008_0199_04.OGG`，即"场景号_行号_角色编号"。场景号和剧本 epub 的章节号是一致的（"剧本 1008"）。
- 每个主要角色挑 10–20 秒干净、情绪平稳的单句作为参考音频。
- 已有解包工具和对照表：`~/codes/github.com/thalesfu/gameresource/acg/白色相簿2`。`Dev/产出/语音对照.tsv` 给出每一句台词对应的说话人和语音文件；`Dev/tools/lscr.py` 能导出中文和日文正文（JSON 里带语音文件名）；`lacpak.py` 能按通配符抽语音。
- 角色编号：`00` 春希（18221 条，春希有配音）、`01` 和纱、`02` 雪菜、`03` 小春、`04` 千晶、`05` 麻理、`10` 武也、`11` 依绪、`15` 孝宏、`16` 曜子、`19` 朋，`12`–`37` 是各个配角，`98`／`99` 是群众和龙套共用的。
- 这本 epub 就是 `daily.py` 生成的 Obsidian「每日对话」再排版出来的。试做片段 A 对应剧本 `2024`，B 对应剧本 `3014`。

**读音**：有注音的地方只念正文，注音丢掉（`机场<rt>这里</rt>` 念"机场"）。每本书维护一份读音表（词 → 拼音）：先由 LLM 从角色表和生僻词里生成初稿，合成前统一套用；试听时发现读错的再补进去。

**输出**：每个 epub 章节出一个 MP3，按"部"分文件夹，例如 `第二部-共通/012 2010-11-24 周三.mp3`。规格为 44.1kHz、160kbps 联合立体声。ID3 里写好书名、章节名、曲目序号和封面。

**立体声定位**：旁白和心理活动放正中间。台词按角色固定往左或往右偏一点，不超过 ±20%，听对话时容易分清是谁在说。混响做成立体声。

**剧本化用的 LLM**：脚本里用无界面模式调用 Claude Code（`claude -p`），按章节逐个处理，输出的 JSON 先按 schema 校验。用的是现有订阅，不另外开 API。

**中间格式**：每本书产出三份文件，都放进 git，可以手改，也可以重跑：
- `cast.yaml`：角色表，记录档位、性别年龄、音色描述、复刻参考音频路径、立体声偏移。
- `lexicon.yaml`：读音表。
- `script/<章节>.jsonl`：一行一句，字段为 `{idx, type: 旁白|台词|心理活动, speaker, effect: 无|电话|回忆|书信短信, text, instruct?}`。

合成这一步只读这三份文件。代码放在 readbook 仓库里，用 Python。

**试做片段**：两段一起试，合计约 5800 字、成品约 23 分钟。
- **A**：ch066「2011-01-01 周六」（雪菜线·新年），约 3200 字。测主要角色、`？？？` 认人、电话效果、回忆里的 `『』`，以及 `<em>` 的拆分。
- **B**：ch195「2013-01-26 周六」（终章），约 2600 字。测龙套、书信短信（雪菜的邮件），以及几处边角情况：不带名字的回放台词、不带引号的和纱台词、只有标签的 ruby。

**试做交付物**：
- 剧本化跑两种：一种走结构捷径；另一种是盲测，把名字全部去掉、当普通小说跑，再用原书标记当标准答案算准确率。
- MP3 出四个版本：
  1. 本地版，内心用后期处理；
  2. 本地版，内心用模型指令；
  3. 本地版，逐句用原声做情绪参考：只作用于有原声的台词，音色仍由固定参考音频决定；
  4. 豆包预置音色对照版。
- 一张实测表：本地实时率、推算全书耗时、读错的词清单。同时核实"悬着"里的各项。

**试做通过标准**（三条都满足才开始做全书）：
- 盲测时，有名字台词的说话人准确率 ≥95%。
- 试听认可：角色分得清，同一角色的音色前后稳定，读错的地方不多。
- 按实测速度，全书能在一周内挂机跑完。

**心理活动的内心处理**：还没定。试做时做两个版本对比：一版是后期处理（ffmpeg 压低音量、加混响和近讲 EQ），一版是模型指令（"轻声自语"之类），听完再选。

**音色流程（第二轮小样后定）**：
- 引擎：Qwen3-TTS Base 带文本复刻，采样温度 0.6。
- 参考音频：每个角色先挑音高、语速最接近平时状态的原声，再用 VoxCPM2 加说话风格生成中文定妆音，逐句复刻都以中文定妆音为参考。
- 音色锚点：每个角色只认一段中文定妆音作为锚点。按"音高、语速最接近这个角色原声"挑，语速明显偏快或偏慢的候选不要。Qwen3 复刻会跟着锚点的节奏走，而且不支持调语速，锚点一快，后面就得大幅变速，声音会发僵。
- 音色质检：用 CAM++（中文说话人识别模型）算相似度，实测同一个人 0.7–0.8，不同角色 0.2–0.5。它只当门槛用（低于 0.65 就重做、不采用），不拿来挑"最像"的。按最像原声挑出来的春希锚点语速偏快，试听反而生硬。
- 变速只在偏差很大时才做，并且限制幅度。
- 分情绪：剧本化时由 LLM 给每句标情绪。情绪定妆音一律从锚点派生（以锚点为参考，加情绪指令生成），和锚点的相似度达到 0.75 才采用；达不到的情绪直接用锚点。
  - 主要角色 10 种：平常、开心、兴奋、生气、难过、哭腔、害羞、冷淡、惊讶、轻声。
  - 配角 3 种：平常、激动、低落；龙套只用平常。
  - 春希的旁白和心里话另有一段"讲述"定妆音。
  - LLM 先读候选原声、按情绪分类，从每类里挑几句，它们的中文译文当派生时要念的文字。
  - 某种情绪没有素材、或者派生出来不像本人，就往回退：哭腔→难过→平常，惊讶→兴奋→开心→平常，害羞→轻声→平常，冷淡、生气→平常。
- 质检：音高、语速、句内变调超标就重做，最多 5 次取最好；语速最后拉回目标的 0.85–1.2 倍。

**试做实测**（详见 [小说转有声书试做结果](小说转有声书试做结果.md)）：
- **合成速度**：本地实时率是后期处理版 1.17、指令版 1.74。全书约 108–138 小时音频，后期处理版约 5.3 天跑完，指令版约 10 天。
- **跨语言复刻**：用日语参考音频复刻后说中文，正常长度的句子识别字错率中位数为 0，能听懂；极短的感叹句偶尔不稳。
- **逐句原声做情绪参考**：把日语原声当续写提示，模型会顺着说日语，108/225 句识别不出来，这种做法不可行。
- **读音纠正**：VoxCPM2 和 Qwen3-TTS 的文档都没提拼音标注，所以读音表就用同音常用字替换。
- **盲测准确率**：93.0%，没达到 95%。错的都是去掉名字后原文本身分不清的句子，换 opus 也只有 93.6%。
- **失控保护**：只有标点的句子插静音不合成；超过"2.5 秒 + 每字 0.5 秒"判定为失控，按"换种子 → 去掉指令或提示 → 退回后期处理版"的顺序处理。

## 决策

### 通用方案加结构捷径

需求本身是"小说转有声书"，测试素材恰好是标记规整的剧本。定为通用方案，带结构标记的书走解析捷径。只为这一本书做，换一本普通小说就用不了；把它当普通小说跑 LLM，又浪费了现成的标准答案。

### 允许复刻声优

推荐的做法是只用设计音色和预置音色，这样什么模型都能放心用。最后定为可以复刻声优：只给自己听，角色声音越接近原作越好。代价是排除了协议禁止模仿真人的引擎。云服务的复刻条款一般要求取得授权，所以复刻大概率只能用本地模型来做。

### 本地为主，云端只做对照

候选有三种：云端为主（豆包，¥400–500 加音色槽位）、本地为主、两者混合。复刻声优基本只能在本地做，所以定为本地为主。豆包只在测试时拿来对照，用来判断本地音质差多少。代价是本地合成速度还不知道。

### 第一人称小说的旁白用主角音色，并且把心里话单独拆出来

视觉小说的叙述就是主角的内心，所以"旁白"和"心理活动"在原文里是混在一起的。另外两个选项都放弃了。一个是一律用独立旁白：第一人称的"我"被别人读出来很别扭。另一个是 `<em>` 全部当内心处理：62 万字都是耳语腔，听久了累。代价是多一步 LLM 分类。

### 旁白改成主角音色的"讲述模式"

原定第一人称小说的旁白直接用主角音色。试听后发现旁白和春希的台词分不出来，于是改成：同一个音色，但旁白另做一段平静低缓的讲述定妆音，混音上让旁白贴耳、台词有房间感。没有改用独立旁白音色，因为第一人称的"我"被别人念出来很别扭。

### 分情绪做定妆音

依绪喝醉后兴奋大喊的两句（#56、#58）重试 5 次都不像她：音高冲到 296 Hz，进了雪菜的音区。原因是定妆音只有一段平淡的语气，模型硬演兴奋，就把音色一起演丢了。所以每个角色改为按平常、激动、低落各做一段定妆音。另一个办法是只收紧质检，但参考音频里本来就没有这种情绪，重试多少次也演不出来，所以放弃。

**后来又改了一次**：第一版的各情绪定妆音，是分别从不同的日语原声独立复刻出来的。试听时依绪、雪菜从 #54 起"每个人都很分裂"。用 CAM++ 一量，雪菜的哭腔、惊讶、轻声三段定妆音和她本人的相似度只有 0.36–0.45，比依绪和雪菜两个人之间（0.53）还低；逐句相似度也从 0.80 掉到 0.4 左右。改成现在的做法：每个角色只有一个音色锚点，情绪定妆音从锚点派生，通过音色检查才用。原则是先保证像同一个人，情绪只在不破坏音色的前提下加。

### CAM++ 只当门槛，不当选拔标准

第三轮用 CAM++ 挑"最像原声"的锚点，给春希挑中了一段语速偏快的。合成后整体偏快，又被放慢最多 38%，试听"很生硬"。之前按"音高、语速接近原声"挑的旧锚点，春希、雪菜反而更自然。试听认可的混合版里，春希用的是分情绪版，雪菜用的是低温版，依绪和武也用的是锚点版。所以锚点改回按音高、语速来挑，CAM++ 只用来拦住明显不像的。

### 白色相簿2 改读游戏数据，不解析 epub

原计划是解析 epub 里的标记。后来发现 gameresource 仓库已经把游戏剧本解了出来，每句台词都能对上说话人和语音文件，而 epub 本身也是从这份数据生成的。于是改读游戏数据：`？？？` 不用交给 LLM 猜，还白得一份日文逐字稿，可以走"带文本复刻"。代价是这条捷径只适用于这一本书。

## 悬着

- 云服务（豆包、ElevenLabs 等）的声音复刻条款是否允许上传未经授权的声优声音 —— 暂按不允许处理，也就是复刻只走本地模型。现在云端只用预置音色做对照，用不到这一条；以后想在云端复刻时，再去查对应平台的条款原文。

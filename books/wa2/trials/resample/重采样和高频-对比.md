# 19 号票：修转 48 kHz 的镜像，试高频处理

## 定论

- **镜像修掉了**：三处线性插值（`bakeoff.to48k`、`bakeoff.cmd_index`、`voices.Pak.audio`）换成一个 `voices.to48k`，用 soxr（HQ）重采样，所有路线都走它。
  - 成品 11–16 kHz 原来是 −33～−37 dB，修后 −84～−88 dB，只剩噪声底；
  - 线性插值还把 4–11 kHz 压暗了 2–6 dB，修后这一段更亮。
- **重新挑选只变了一句**：不重新合成，拿现成候选重新挑选、混音。小样 43 句里 10 号换了候选，〈2002〉58 句都没变。
- **高频处理用"缓4k"**：一阶低通，4 kHz 起每倍频程 −6 dB。
  - 用户戴 AirPods Pro 3 听 A/B，原话："C或者D感觉会更好一些"，二选一挑了 D；
  - 指标和只修镜像持平；
  - 写进 `mix.HIGHS_DEFAULT`，旁白和台词用同一档。
- **指标**：修镜像加缓4k，像原声、过门槛、认人、字错率都和修前持平。削得更狠（2.5k、1.5k 起）才开始有代价。
- **颤音没去干净**：IndexTTS-2.5 自带的那部分在 8 kHz 以下（17 号票），缓4k 只能压轻。

## 镜像：修前修后

详表见 [镜像.md](镜像.md)（`uv run python -m readbook.resample 镜像`）。数值是各频段相对 0.1–4 kHz 的 dB，取小样的成品 MP3：

| 转 48 kHz | 4–8 kHz | 8–10 kHz | 10–11 kHz | 11–12 kHz | 12–16 kHz |
|---|---|---|---|---|---|
| 线性插值（修前） | −18.3 | −24.4 | −30.9 | −33.5 | −31.9 |
| soxr（修后） | −16.4 | −19.7 | −25.1 | −84.6 | −86.6 |

- IndexTTS-2.5 原始输出是 22.05 kHz，真实内容只到 11.025 kHz：修前 11 kHz 以上的能量全是镜像，修后没了。〈2002〉一样。
- 线性插值本身就是一个低通（三角核，频响 sinc²），所以修前 4–11 kHz 还被压暗了。拿单个原始候选比：
  - soxr 转出来和 22.05 kHz 原件各段差不到 0.3 dB；
  - 线性插值在 8–10 kHz 低约 5 dB。
- 其他两处：
  - `voices.Pak.audio`：游戏原声抽查下来都是 48 kHz，原来那段插值实际走不到，照样改了；
  - Qwen3 的 24 kHz 输出（`TorchQwen.takes`、`qwen_takes`、VoxCPM）也走 `to48k`，以后生成的锚点不再带镜像；
  - 现有锚点 wav 里还带着镜像，没有重做。IndexTTS 读参考时会重采样到自己的采样率，不影响成品。
- `soxr>=1.1.0` 写进了 `pyproject.toml`。它原来是 librosa 间接带进来的，`uv.lock` 只多了这一项。

## 重新挑选

`uv run python -m readbook.index_passage repick <版本> <片段>`：读 `out/index/<版本>/<片段>/raw/` 的候选，用 `index_passage.pick` 同样的规则重新挑选，成品写到 `out/index/<版本>-重采样/<片段>/`。小样用 `2.5-原声平均锚点新规`，〈2002〉用 `2.5-原声平均锚点全员`（〈2002〉里没有武也，两版一样）。

- **旧的挑选怎么复现**：旧 qc.json 没记挑的是第几个候选。用旧的线性插值，加上旧 qc.json 里存的 CAM++ 相似度，把旧挑选重算了一遍，`tries` 和 `score` 句句对上。现在 qc.json 多记一项 `take`（`bakeoff.finish` 返回挑中的序号）。
- **变了的只有一句**：小样 10 号，春希心里话「………真是，两个本末倒置的家伙。」，从 0 号候选换成 1 号。
  - 旧的 0 号质检分 0.4498，刚好在 0.45 线内；
  - 修后它的音高估计从 141.6 Hz 变成 141.0 Hz，质检分变成 0.4586，没过线；
  - 于是多试了一个候选，1 号的分数 0.411，修前修后一样。
- 候选和锚点的相似度，新减旧中位 +0.002，范围 −0.014～+0.051。

## 高频处理 A/B

`out/resample/ab/高频AB.wav`（不进 git，`uv run python -m readbook.resample ab`）：
- **句子**：17 号票用户标过颤音的春希 7 句（小样 1、4、7、13 号，〈2002〉22、25、38 号），再加雪菜小样 63 号、依绪小样 66 号，主要听闷不闷；
- **怎么放**：每句连着放 6 版；
- **怎么混**：走正式的混音链（响度拉平、台词加房间混响、定位），各版响度一样（−21.2 dB）。

| 版 | 做了什么 | 2 kHz | 4 kHz | 6 kHz | 10 kHz |
|---|---|---|---|---|---|
| A | 修前（线性插值，有镜像），不另处理 | | | | |
| B | 只修镜像 | 0 | 0 | 0 | 0 |
| C | 修 + 压8k（高架，8 kHz 起） | 0 | −1 | −3 | −9 |
| **D** | **修 + 缓4k（一阶低通，4 kHz 起每倍频程 −6 dB）** | **−1** | **−3** | **−5** | **−10** |
| E | 修 + 缓2.5k | −2 | −6 | −9 | −14 |
| F | 修 + 缓1.5k（用户在 Audacity 里做的那种） | −4 | −9 | −13 | −18 |

- **用户的话**："C或者D感觉会更好一些"。
- **二选一定 D**：IndexTTS 自带的颤音在 8 kHz 以下，D 在 4–6 kHz 也压了 3–5 dB，C 在这一段几乎不动。用户也没觉得 D 闷。
- **旁白和台词用同一档**：两类都在 A/B 里，用户没分开提。混音代码里 `process` 对所有类别、所有角色一视同仁。

## 没做、没测的

- 修镜像本身让颤音轻了多少：A/B 里有 A 和 B，用户没单独说；从挑了 C/D 看，光修镜像不够。
- 豆包（`volc_passage`）自己拼段落，不走 `mix.process`，没有加高频处理。那条路线已暂停（14 号票）。
- 现有的 Qwen3 锚点 wav 里还带着镜像，没有重做（对 IndexTTS 成品没影响，见上）。

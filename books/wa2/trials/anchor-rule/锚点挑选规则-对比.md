# 锚点挑选规则补上门槛和音高范围（17 号票）

2026-10-28，RTX 5090 笔记本。和 16 号票的全员版（`books/wa2/trials/rawavg-anchor/*-IndexTTS-2.5-原声平均锚点全员.*`）比。试了两版，产物都在这个目录：

- **试版**：照票的要求，再加一条音高抖动上限。用户试听后去掉了这一条。
  - 产物：`*-原声平均锚点新规试版.*`；
  - 锚点：`锚点-试版/`；
  - 挑选明细：`锚点-试版.yaml`、`锚点对比-试版.md`。
- **定版**：去掉抖动上限，就是现在 `readbook/rawanchor.py` 的规则。
  - 版本名 **2.5-原声平均锚点新规**；
  - 锚点：`锚点/`；
  - 挑选明细：`锚点.yaml`、`锚点对比.md`。

## 定论

- **定版规则**（对所有角色一样，数都从本人原声的分布来）：锚点要没读错、过质检、音高在本人原声的正常范围里、过本人的音色门槛，合格的取像原声最高的；都不合格就换种子多生成，最多 4 批，还没有就放宽质检和音高。
- **定版的锚点**：
  - 春希、雪菜、依绪和全员版是同一个文件；
  - 只有武也换了：7 号 → 14 号（第 2 批），像原声 0.53 → 0.66，过了门槛 0.55；音高 161 Hz（原声 144，7 号 147）。
- **定版的成品**：
  - 〈2002〉里没有武也，和全员版完全一样，没有另做；
  - 小样只有武也那一句（3 号）不同：像原声 0.44 → 0.62，过了门槛。小样过门槛 29/31 → 30/31，认人 100%。
- **音高抖动上限为什么去掉**：A/B 试听里，三个春希锚点的颤音轻重和音高抖动正好排反。试版按它把春希从 0 号换成 1 号，成品听着更抖（7 句平均 1.7 → 2.1）。试了十种别的量法，也没有一种跟得上听感。
- **用户在 AirPods 上听到的电子颤音，查下来有两部分**，都不归锚点挑选管，要另开票：
  - **我们自己的 bug**：`bakeoff.to48k` 用线性插值把 IndexTTS 的 22.05 kHz 输出转成 48 kHz，11 kHz 以上多出一层镜像。去掉能轻一些；
  - **IndexTTS-2.5 原始输出自带的**：在 8 kHz 以下，后期 EQ 去不掉。锚点影响它的轻重，0 号最轻，但没有指标，只能靠听。
- **顺手发现的**（都不是锚点的问题）：
  - 小样 73 号雪菜「～～～呃！？」：句首的「～～～」原样送进了 IndexTTS，读出一个「克」；
  - 对照剧本的时间会出现 "4:60.0"：秒数四舍五入进位，在 `passage.py`。

## 定版规则

`readbook/rawanchor.py`，对所有角色一样。候选仍是原声平均版（Qwen3 只用本人 60 句原声的平均说话人向量）按旧定妆音的文本生成，一批 8 个、固定种子。候选要同时过四条：

1. **没读错**：字错率不比已生成的候选里最低的高出 0.1 以上（16 号票就有）；
2. **过质检**：时长、句内变调、音高语速离目标不太远（16 号票就有，`bakeoff.ok`）；
3. **音高离目标不超过本人原声音高四分位距的一半**（新）：春希 138–185 Hz、雪菜 275–319、依绪 216–264、武也 124–168；
4. **过本人的音色门槛**（新）：像原声 ≥ 本人原声的 P5，和逐句的门槛是同一把尺子。

合格的里面取像原声最高的。**都不合格**（用户定的）：换种子再生成一批 8 个，有合格的就停，最多 4 批；还没有，就放宽第 2、3 条，在没读错、过门槛的里面取像原声最高的。

原声的分布（音色门槛、音高）都取同一批：每人从语音包里按固定种子随机取的 300 句（1.5–15 秒），没有手填的数。

**音高容差：对雪菜不用收紧，对武也要收紧**：

- 雪菜挑中的锚点 308 Hz，比目标 296 高 4%，在她原声的正常范围（四分位距 276–320）里。原来的质检容差已经够，再收就得手填一个数，而且换掉它像原声要掉 0.05。
- 武也是另一回事。质检是音高、语速合起来打分，语速贴目标时音高高两成也能过：多生成的候选里 18 号 176 Hz（比目标高 22%）质检分 0.442，刚过 0.45 的线，像原声 0.66。没有第 3 条，它就会被挑中。
- 锚点的音高会带进成品（16 号票：雪菜锚点 276 → 308 Hz，成品 275–291 → 311–320；武也锚点 175 → 147，成品 190 → 152）。春希例外，锚点 174 Hz，成品平常台词 160。
- 所以第 3 条用本人原声的音高分布定容差。四个人里只有武也被它改了结果。

```
uv run python -m readbook.rawanchor          # 定版规则：打分、挑选，写 锚点.yaml 和 锚点对比.md

uv run python -m readbook.index_passage 2.5-原声平均锚点新规 小样
uv run python -m readbook.index_passage pair 小样 2.5-原声平均锚点全员 2.5-原声平均锚点新规

```

## 音高抖动这个指标靠不靠得住

`qc.jitter` 照搬 16 号票对比文档的算法：pyin 每 10 毫秒一个音高，只看连续有声不短于 0.3 秒的段，减掉 0.3 秒滑动平均，去掉两头各半个窗口和 |残差| ≥ 300 音分的帧，取稳健标准差。16 号票的数（85、13、37）能逐个复现。问题是**它测得很少**：

- 两头各去半个窗口，一段有声要不短于 0.46 秒才留得下东西。中文合成句的有声段多在 0.2–0.45 秒，日语原声也差不多：
  - 春希原声 300 句只有 143 句测得出，其他人 205–229 句；
  - 8 个春希候选里 3 个测不出。
- 测得出的也只基于很少的帧：
  - 春希 0 号的 85 来自 54 帧（0.54 秒）；
  - 1 号的 37 来自 25 帧；
  - 旧定妆音的 13 来自 36 帧。
- 换一种不丢两头的滑动平均（窗口在边上自动缩短），能多测出很多，但数会变：
  - 春希 0 号和 1 号变成 94 和 115，大小反过来了；
  - 原声上两种算法的相关只有 0.5–0.7。

所以锚点本身的抖动只是个粗指标。试版规则照票的要求用它当门槛，春希因此换了锚点；换得对不对，要看下面的成品和试听。

## 削掉高频以后颤音轻很多

- **用户的做法**：用 Audacity 4 处理了 A/B 文件，导出到 `out/rawanchor/ab/变体/audocity.wav`。用户的话："这个好很多，这个 0 号好很多"。
- **反推出来的处理**：拿它和原文件比传递函数，是一个很缓的低通，加整体提升约 5 dB：
  - 每倍频程 −6 dB，转折点约 1500 Hz，就是 Audacity 低通滤波器的默认滚降；
  - 1.5 kHz −3 dB、3 kHz −7 dB、6 kHz −12 dB、16 kHz −19 dB（相对低频）；
  - 全段一样处理，相干 1.00。
- **说明**：
  - 听感上的电子颤音主要在 2 kHz 以上的高频，不在低频。之前"颤音在基频那一段"的猜测不对；
  - 耳机把高频的细节直接送进耳朵，笔记本扬声器加上房间反射会把它抹平，所以 AirPods 上明显、扬声器上好很多；
  - 0 号锚点那版处理后最好，和 A/B 的标记一致。
- **这是混音（后期 EQ）能管的事**：一个缓的高频衰减可能就够。它和锚点挑选规则无关，混音在 `mix.py`，要另开票试：
  - 转折点和斜率；
  - 只削某一段，比如 2–5 kHz 还是 5 kHz 以上；
  - 对清晰度、读音的影响；
  - 旁白和台词要不要一样。

## 只听全员版，逐段压高频

`out/rawanchor/ab/全员/`：同样 5 句全员版（0 号锚点）的春希，只换处理。用户试听：

- 2（缓低通 1500 Hz）"确实变轻了"；
- 7（只压 8 kHz 以上 12 dB）"好很多，但是还有一些"；
- 3–6（分别只压 1–2、2–3.5、3.5–5、5–8 kHz）没提。

**很可能的原因：转 48 kHz 时的镜像**

- IndexTTS-2.5 的原始输出是 22.05 kHz，真实内容只到 11 kHz；
- `bakeoff.to48k` 用线性插值（`np.interp`）转到 48 kHz，没有抗镜像滤波，11 kHz 以上多出一层镜像：真实频谱按 11.025 kHz 翻折上去的假音；
- 量出来：
  - 原始候选 12 kHz 以上没有能量；
  - 成品 wav 12–16 kHz 有 −33 dB，比 10–11 kHz 的 −39 dB 还高，真实的高频不会这样；
- 镜像的频率随音高反着走，听起来像电子味的颤音；
- 笔记本扬声器放不出 10 kHz 以上，AirPods 放得出来，正好对上；
- 压 8 kHz 以上（7）最有效，因为它把镜像压了 12 dB。剩下的"还有一些"可能就是没压干净的镜像。
- Qwen3 的锚点（24 kHz 输出）也是这样转的，也带镜像。IndexTTS 读参考时会重采样到自己的采样率，应该不影响成品。

验证用的两个文件：

- 8：陡低通 10.8 kHz，只去掉镜像，真实内容不动；
- 9：只留镜像本身。

8 如果不抖了，修法就是把 `to48k` 换成正经的重采样（带抗镜像滤波）。不用重新生成：原始候选是 22.05 kHz 的，重新挑选、混音就行。`to48k` 在 `bakeoff.py`，Qwen3 的路线也用它，影响面比锚点规则大，要另开票改。

**验证结果**（用户试听）：

- 8（只去掉镜像）"还有一些"；
- 10（从原始候选正经重采样）、11（再压 8 kHz 以上）、12（再去掉 8 kHz 以上）"三个都还有"。
- 这 5 句挑中的都是第一个候选，也没变速（长度和原始候选一样），所以变速不是原因。

**结论**：电子颤音有两部分。

- **转 48 kHz 的镜像**：是我们自己的 bug。修掉能轻一些（7、8），但不是全部。
- **IndexTTS-2.5 原始输出本身就有，在 8 kHz 以下**：去掉 8 kHz 以上也还在。
  - 后期 EQ 只能让它轻一点（缓低通 1500 Hz 那种，代价是声音变闷），去不掉；
  - 锚点会影响它的轻重（0 号最轻），但眼下没有能跟上听感的指标。
